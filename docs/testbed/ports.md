# 포트 대장

## 1. 규칙

- 40000–40999를 쓰고, 테스트베드마다 **10개 블록**을 줍니다.
  - `+0`: 대시보드 + 제어면(`PORT`)
  - `+1`–`+9`: 데이터면
- 이 대장이 유일한 배정 기록입니다. **새 테스트베드는 블록을 이 표에 등록하는 일부터 시작합니다**(`testbed-base`에 PR).
- 다음 블록은 표의 마지막 블록 다음 10개입니다. 비거나 반납된 블록을 다시 쓰지 않습니다.
- 데이터면 포트도 env(`<CORE_ID>_PORT` 등)로 바꿀 수 있습니다. 클라우드에서 여러 인스턴스를 띄울 때 씁니다. 대장은 기본값만 기록합니다.

## 2. 배정

| 블록        | 레포                   | +0 (대시보드·제어면) | 데이터면                                                                      | 상태 |
| ----------- | ---------------------- | -------------------- | ----------------------------------------------------------------------------- | ---- |
| 40000–40009 | `testbed-base`         | 40000                | 40001: 샘플 코어(TCP echo), 40002–40008: 예제 외부 코어 `py-echo`(복제 r0–r6) | 사용 |
| 40010–40019 | `slack-agent-org-dash` | 40010                | 없음(파일을 읽는 관찰 코어라 데이터면 포트를 열지 않음). 40011–40019는 예비   | 사용 |

## 3. WSL2/Windows 주의

Hyper-V가 40000번대 일부를 예약해 두는 경우가 있습니다. 예약된 포트는 열 수 없습니다(`EACCES` 또는 `EADDRINUSE`).

1. 예약 범위를 확인합니다(Windows PowerShell 또는 cmd).

   ```
   netsh interface ipv4 show excludedportrange protocol=tcp
   ```

2. 결과 범위가 이 테스트베드의 블록과 겹치면, 그 포트를 env로 겹치지 않는 값으로 바꿔 띄웁니다. 대장은 고치지 않습니다.
3. 겹침이 계속되면 관리자 권한으로 `net stop winnat` → 테스트베드 기동 → `net start winnat` 순서로 예약을 피할 수 있습니다. 이 방법은 다른 프로그램의 네트워크에도 영향을 주므로 사람이 직접 판단해서 합니다.
